# Android 高清预览模式设计

## 目标

Android 先拆出两个明确模式，避免高清预览、缩略图后台加载和批量下载同时抢相机 PTP 通道。

- 选择下载模式: 网格浏览、多选、批量下载。
- 高清预览模式: 顺序加载高清预览图，退出后再开始下载。

底层约束不变: 同一时刻只能有一个相机 PTP 读取请求运行。

## 产品行为

### 选择下载模式

- 保持现有网格、多选、全选、批量下载体验。
- 优先加载可见缩略图。
- 批量下载开始后，下载独占 PTP，后台缩略图和 metadata 不能插队。

### 高清预览模式

- 进入后显示单列或双列高清预览列表，默认先按单列实现。
- 不再继续加载大量缩略图。
- 不立即启动下载。
- 当前可见照片优先加载高清预览。
- 当前照片完成后，按照片顺序依次向后加载高清预览。
- 用户跳到某张照片时，该照片立即提到最高优先级。
- 已加载过的高清预览直接使用缓存。
- 用户在该模式下点下载，只加入下载队列，不马上抢 PTP。
- 退出高清预览模式后，开始或恢复下载队列。
- 如果本次高清预览队列全部加载完成，可以自动开始下载队列。

建议 UI 状态:

- `高清预览加载中 12 / 80 · 下载将在退出后开始`
- `已加入下载队列`
- `高清预览已完成 · 开始下载`

## 调度规则

高清预览模式 active 时:

1. 允许 `PreviewImage` 请求。
2. 暂停 `DownloadOriginal`。
3. 暂停 `VisibleThumbnail` / `PreviewNeighborThumbnail`。
4. 暂停 `BackgroundMetadata`。
5. 任何 PTP 操作仍必须通过共享调度器串行执行。

高清预览模式 inactive 时:

1. 停止高清预览顺序预加载。
2. 恢复下载队列。
3. 恢复缩略图和 metadata 后台任务。

## 高清预览协议

高清预览不使用当前 256KB partial fallback。应按原厂 screen preview 语义实现:

1. `D226 ImageForceCompression = 1`
2. 重新读取 `ObjectInfo(handle)`
3. 使用新的 `ObjectInfo.compressedSize`
4. `GET_PARTIAL_OBJECT(handle, 0, compressedSize)`
5. 校验图片完整性
6. `finally` 恢复 `D226 = 0`

失败时保留缩略图显示，并记录诊断日志。

## 缓存

第一阶段:

- 内存缓存最近 20-30 张高清预览。
- cache key 至少包含 handle 和 fresh ObjectInfo 尺寸信息。

后续阶段:

- 增加磁盘缓存，避免退出再进时重复读相机。
- cache key 扩展为 `cameraId + handle + compressedSize + modifiedTime + previewMode(D226=1)`。

## 下载关系

高清预览模式期间下载不抢 PTP:

- 用户可继续选择/加入下载队列。
- 下载状态显示为等待。
- 退出高清预览模式后再下载。
- 如果全部高清预览已加载完，也可以自动开始下载。

该阶段不做“边预览边分片下载”。这可以降低 PTP 状态切换复杂度，优先保证不串图。

## 日志和验证

需要新增或调整诊断日志:

- 进入/退出高清预览模式。
- 每张高清预览请求开始、完成、失败。
- `D226=1` 设置和 `D226=0` 恢复。
- preview bytes、decoded size、elapsedMs。
- 下载因高清预览模式暂停/恢复。

验收标准:

- 高清预览模式下不会出现下载 PTP 请求。
- 下载模式下不会出现后台 metadata/缩略图插入下载。
- 打开大图先显示已有缩略图，随后替换为高清预览。
- 退出高清预览模式后，下载队列开始执行。
- `D226` 失败或取消时也会恢复为 0。
